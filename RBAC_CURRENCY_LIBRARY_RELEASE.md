# Row-scoped access, multi-currency reporting and document library

## What was requested

> “lETS MAKE SURE THE ROLE BASED ACCESS IS WORKING, BECUASE NOW EVERY ACCOUNT I LOGIN WITH SHOWS SAME DATA, ALSO ASS MULTI CURRENCY IN SETTINGS, ALSO DOCUMENTS AND DRAWINGS SHOULD HAVE WHERE WE UPLOAD THE FILES IN FOLDERS ETC”

Confirmed decisions:

- **RBAC:** row-scoped. Only **Owner** and **Admin** see the whole company. Other internal staff see their department, shared master data, their own staff record and records on jobs assigned to them. External client/subcontractor portal scoping stays in place.
- **Currency:** full base-currency conversion. Settings manages the base currency, enabled currencies and editable manual exchange rates; dashboards, reports, wallets and job 360 totals report in the base currency while records keep the currency they were entered in.
- **Folders:** both automatic and custom. Every job gets **Drawings / Contracts / Site photos / Handover**; users can create nested custom folders, upload, browse, search, keep revisions and open the owning record.

## What changed

### 1. Real row-level access

- `src/lib/catalog.ts` defines `FULL_ACCESS_ROLES`, shared master-data resources and department registers.
- `src/lib/access.ts` builds a server-side scope from `app_staff_project_ids`, `app_employee` and the external portal rules. It fails closed for internal wallets when no scope is supplied.
- `supabase/migrations/20261110130000_staff_scope.sql` is generated by `npm run rbac:staff` from those catalog arrays. It adds `memberships.staff_employee_id`, `attachments.folder_key`, `public.document_folders`, staff SQL helpers, and overrides `app_visible_record` / `app_wallet_client_allowed`.
- Live Supabase migrations applied: `staff_scope_and_document_folders`, `staff_scope_manager_create`, `staff_scope_refinements_v2`. The latter denies all-wallet access to unassigned staff, scopes folder edits/delete to visible jobs and restricts audit-log reads for internal staff. Repository files `20261110131000_staff_scope_manager_create.sql` and `20261110132000_staff_scope_refinements.sql` mirror those live refinements.
- Settings → Users & roles can link each internal account to its staff record and assigned jobs; new invites can carry that link from the start.
- Dashboard KPIs, counts, command-palette search, wallet lists/detail, library files and project 360 all respect the same scope.

### 2. Multi-currency settings and reporting

- `src/lib/currency.ts` holds the currency catalogue, manual rate normalisation and base-conversion helpers. Rates are stored as `units of currency per 1 base unit` and are re-expressed correctly when the base currency changes.
- Settings → **Currencies** supports base currency, enabled currencies, manual rates, a live conversion example and an audit-log entry on save. The General tab’s base-currency field stays consistent with the Currencies tab.
- Dashboard, Reports, Client wallets, project 360 and PDF totals use `data.currency` / `ov.fx`, `toBase`, `sumInBase` and `currencyBreakdown`. Wallet summary totals are converted too; individual wallet rows still show their original currency.
- PDFs keep document fields in their entered currency and print an additional reporting total with the rate when the document currency differs from the base.

### 3. Document library

- New `/${ORG}/library` page and sidebar entry under **Jobs & sites**.
- `src/lib/document-folders.ts` derives one folder per job and the four automatic buckets. `src/lib/folders.ts` resolves any folder key against scoped project visibility.
- `src/app/api/[org]/library/route.ts` lists scoped projects/folders/files and supports `createFolder`, `renameFolder`, `deleteFolder` and `moveFile`. Moving a document keeps every revision together.
- `src/app/api/[org]/files/route.ts` creates a controlled `documents` register row for library uploads, preserves revision chains and writes `attachments.folder_key`. Storage paths remain `<org-uuid>/<record-id>/<uuid>-<safe-name>`, so `app_storage_allowed` is unchanged.
- The library UI supports breadcrumbs, automatic/custom folders, multi-file upload, file search, newer/older revisions, download, rename/delete/move controls and a **Record** link back to the owning register row.
- Library file and folder visibility is filtered by both the owning record and the folder’s project scope; direct file download denies hidden-folder files.
