# Workspace-aware conversion drawer

The conversion API filters returned stages by BOTH enabled module and enabled resource, plus role read permission. Disabled stages and their record links are not returned. Source-provenance links require enabled/readable resources and a scoped record lookup. Displayed stage counts come from the filtered response, not the global nine-stage definition. Missing enabled links say “No linked record”, not “Skipped”. Quotations use the requested terminology.

Conversion options use the same workspace-adapted rule in GET and POST. Quote/tender awards create a job alone when Contracts is disabled (either module or resource switch). When Contracts is enabled, the existing job-plus-prime-contract rule remains unchanged; lack of contract permission does not silently strip a required operation. Disabled target modules are never offered. Enabled/readable options display a specific permission/account/billing blocker instead of an unusable create button. Existing target links remain available to readers and are not counted as available creation actions. Payment actions require enabled/readable/writable Payments plus create capability and writable billing; receipt conversion remains disabled in favour of the existing settlement flow.

This change does not add quotation-to-invoice conversion, automatically enable modules, alter financial calculations or rewrite existing provenance. It does not address the pre-existing conversion transaction/concurrency limitations.

Validation: `npx tsx scripts/conversion-visibility-qa.ts`, TypeScript and production build passed. Tests cover module/resource switches, role visibility, lean job awards, unchanged full rules and write blockers. Real authenticated conversion writes have not been exercised in this change. Before release, check lean and full workspaces, disabled modules with existing linked records, read-only roles/billing, existing-job links, and GET/POST rule parity on staging. No deployment was performed as part of this implementation.
